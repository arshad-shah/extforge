ExtForge discovers entry points by convention. This page documents both layouts: the **named layout** (new in this release), where entrypoints are found by name in `src/` and the manifest is generated for you, and the **legacy layout** (`src/ui/…`, `src/content/…` plus entry paths written in `extforge.config.ts`), which keeps working unchanged through every 1.x release.

## Named layout (recommended for new projects)

Put entrypoints directly in `src/` under these names. Only these names count, so shared code such as `src/lib/` or `src/components/` is never mistaken for an entry.

```
src/
  background.ts            → background.js (service worker; Firefox: background.scripts)
  popup.html               → popup.html + popup.js (action.default_popup)
  options/index.html       → options.html + options.js (options_page / options_ui)
  sidepanel.html           → sidepanel.html (side_panel; Firefox: sidebar_action)
  devtools.html            → devtools.html (devtools_page)
  newtab.html              → newtab.html (chrome_url_overrides; also history / bookmarks)
  offscreen.html           → offscreen.html (no manifest key; open with chrome.offscreen)
  audio.offscreen.html     → audio.html (another offscreen document)
  frame.sandbox.html       → frame.html (sandbox.pages, Chrome and Edge)
  welcome.html             → welcome.html (unlisted page: open it with runtime.getURL)
  content.ts               → content-scripts/content.js
  github.content.ts        → content-scripts/github.js
  youtube.content/index.ts → content-scripts/youtube.js
  widget.csui.tsx          → content-scripts/widget.js (Shadow-DOM UI, see CSUI)
  hook.injected.ts         → injected/hook.js (page's main world, web-accessible)
  scrape.unlisted.ts       → scrape.js (classic script, e.g. for scripting.executeScript)
  lib/, components/ …      → ordinary code, imported by the entries
```

Any page also works as `<name>/index.html`, and any suffixed script as `<name>.<suffix>/index.ts`. Entries a browser can't use (a `history` override or sandbox page on Firefox, an offscreen document on Firefox or Safari, the side panel on Safari) are still built, but left out of that browser's manifest with a warning. Chrome allows only one URL override per extension, so declaring two fails the build. So do two entries that would write the same file, such as `welcome.html` and `welcome.unlisted.ts`.

- **Pages** (`popup`, `options`, `sidepanel`) are an HTML file, `<name>.html` or `<name>/index.html`. ExtForge bundles each `<script type="module" src="…">` it loads (`./popup.ts` works directly) and rewrites the tag to point at the built file.
- **Content scripts** declare their options in the file. The build reads them without running the file, adds the `content_scripts` entry, and calls `main()` when the script is injected:

  ```ts
  // src/github.content.ts
  import { defineContentScript } from 'extforge/entrypoints';

  export default defineContentScript({
    matches: ['https://github.com/*'],
    runAt: 'document_idle', // also: excludeMatches, allFrames, matchAboutBlank, world
    main() {
      console.log('on github');
    },
  });
  ```

  Options must be literal values. A content script without `matches` is still built but left out of the manifest, with a warning.
- **The manifest is generated** from what's found. Anything you set in `config.manifest` (name, permissions, icons, `action.defaultTitle` …) is kept, and keys you set yourself win.
- Two files claiming one entry (`popup.html` and `popup/index.html`) fail the build, naming both.

**Which layout a project uses.** The legacy layout stays in effect while `extforge.config.ts` writes entry paths (`background.entrypoint`, `action.defaultPopup`, `optionsPage`, `sidePanel.defaultPath`, `contentScripts[].js`), or while `src/ui/` or `src/content/` exists. Nothing about those builds changes. Each build prints a deprecation warning naming what keeps the project there. To move over, run `extforge migrate-layout` (see [Moving to the named layout](/guides/migrate-named-layout/)). The `src/injected/` and `src/contents/` folders keep working in both layouts.

<Aside type="tip">
For React Fast Refresh, give a page its own folder (`src/options/index.html` plus its components beside it). Edits inside the folder hot-swap without a reload. See [HMR](/guides/hmr/).
</Aside>

## Legacy layout

### At the project root

```
my-extension/
├── extforge.config.ts   # Build config — the only required file
├── package.json
├── tsconfig.json
├── icons/               # Extension icons (all sizes required)
├── public/              # Static assets copied verbatim into every dist/<browser>/
├── tests/               # Vitest unit tests
└── dist/                # Build output — gitignored
```

**`extforge.config.ts`** is the only file ExtForge requires at the root. Everything else is discovered from it or by convention. See the [configuration reference](/reference/config/) for all options.

**`dist/`** is recreated on every build. Add it to `.gitignore` (the scaffold does this automatically).

### Inside `src/`

```
src/
├── background/
│   └── index.ts         # Service worker entry
├── content/
│   └── index.ts         # Content script entry (or index.ts for single, *.ts glob for multi)
├── ui/
│   ├── popup/
│   │   ├── index.html   # Popup HTML shell
│   │   └── index.tsx    # Popup React entry
│   ├── options/
│   │   ├── index.html
│   │   └── index.tsx
│   └── sidepanel/
│       ├── index.html
│       └── index.tsx
├── components/          # Shared UI components
├── hooks/               # Shared React hooks
├── store/               # Zustand store modules
├── lib/                 # Utility functions
└── styles/
    ├── globals.css      # Global styles
    └── content.css      # Content script styles (injected into host pages)
```

### `src/background/index.ts`

The service worker entry point. ExtForge bundles this as an ESM module (MV3 supports `"type": "module"` for service workers in Chrome 116+). The output is placed at `dist/<browser>/background/index.js` and registered in the generated manifest.

### `src/content/index.ts`

The content script entry. For a single content script, use `src/content/index.ts`. For multiple scripts targeting different pages, add named files under `src/content/` — ExtForge registers each as a separate content script entry. Content scripts are bundled as IIFE (not ESM) because the content script execution environment does not support ES module imports.

### Injected scripts

Injected scripts run in the page's JavaScript realm (not the extension's isolated world). Place them at `src/injected.ts` for a single script or `src/injected/*.ts` for multiple. These are also bundled as IIFE and must be listed in `manifest.web_accessible_resources` — ExtForge does this automatically.

### `src/ui/popup/`

The toolbar popup. ExtForge expects `index.html` as the HTML shell and `index.tsx` (or `index.ts` for vanilla) as the entry. The HTML file must contain a `div#root` for React or the equivalent mount point for your framework. The scaffold generates both files.

### `src/ui/sidepanel/`

The browser side panel (Chrome 114+, Edge). Same structure as popup. Not supported by Firefox — ExtForge omits the side panel from Firefox builds automatically.

### `src/ui/options/`

The options page, opened via `chrome.runtime.openOptionsPage()` or the browser extensions UI. Same structure as popup.

## `icons/`

```
icons/
├── icon-16.png    # Required
├── icon-32.png    # Required
├── icon-48.png    # Required
├── icon-128.png   # Required
└── icon.svg       # Optional — source for extforge icons regeneration
```

All four PNG sizes are required. The manifest references them by size. If you include `icon.svg`, run `pnpm exec extforge icons` to regenerate all PNG sizes from the SVG (requires `sharp`).

<Aside type="caution">
Missing icon sizes produce an `EXT_MANIFEST_MISSING_ICON` error at build time. The build fails — it does not produce a manifest with missing icon references.
</Aside>

## `public/`

Any file placed in `public/` is copied verbatim into every `dist/<browser>/` at the end of each build. Use this for static assets like `_locales/`, fonts, or images referenced from your HTML files.

## `tests/`

```
tests/
├── extension.test.ts    # Unit tests (vitest)
└── e2e/
    ├── fixture.ts       # Playwright extension fixture
    └── smoke.test.ts    # End-to-end smoke test
```

Vitest unit tests live directly in `tests/`. The scaffold generates a `vitest.config.ts` that includes the `extforge/testing/vitest` setup file, which installs `chrome.*` API fakes automatically — no manual mocking needed. See the [Vitest preset reference](/reference/testing/vitest-preset/) for the full list of faked APIs.

The `tests/e2e/` directory contains Playwright tests. The scaffold generates a fixture that launches Chrome with the extension loaded, so your tests can interact with the popup, options page, and content scripts directly.

## `dist/<browser>/`

```
dist/
├── chrome/
│   ├── manifest.json    # Generated for Chrome MV3
│   ├── background/
│   │   └── index.js
│   ├── ui/
│   │   └── popup/
│   │       ├── index.html
│   │       └── index.js
│   └── icons/
└── firefox/
    ├── manifest.json    # Generated for Firefox MV3 (with gecko_id)
    └── ...
```

Each browser gets its own output directory. The manifests differ by browser — ExtForge handles the per-browser differences (gecko ID for Firefox, `side_panel` for Chrome, etc.). Load `dist/chrome/` or `dist/firefox/` as an unpacked extension.

## What ExtForge picks up automatically

| File / directory | Auto-registered as |
|---|---|
| `src/background/index.ts` | Service worker |
| `src/content/index.ts` | Content script (IIFE) |
| `src/injected.ts` | Injected script (IIFE, web-accessible) |
| `src/injected/*.ts` | Multiple injected scripts |
| `src/ui/popup/index.html` | Copied to `dist/<browser>/ui/popup/` |
| `src/ui/options/index.html` | Copied to `dist/<browser>/ui/options/` |
| `src/ui/sidepanel/index.html` | Copied to `dist/<browser>/ui/sidepanel/` |
| `icons/icon-*.png` | Manifest icon sizes |
| `public/**` | Copied to `dist/<browser>/` |

In the legacy layout these are built, but the manifest only lists what `extforge.config.ts` declares: `background.entrypoint`, `action.defaultPopup`, `optionsPage`, `sidePanel.defaultPath` and `contentScripts`, written as built paths such as `ui/popup/index.html`. Only one content script, `src/content/index.ts`, is discovered. For several content scripts, use the named layout. See the [configuration guide](/guides/configuration/).
